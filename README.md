# Тендер-Сверка

AI-инструмент сверки тендерной документации заказчика с заявками участников (госзакупки и корпоративные закупки
Республики Узбекистан). Из документации он строит атомарный чек-лист требований, сверяет с ним пакет заявки
и считает процент соответствия. По каждому несоответствию он даёт конкретное действие, а каждый вывод
подкрепляет ссылкой на файл, страницу и цитату.

**Демо:** https://massonedrew-dotcom.github.io/tender-sverka/. Демо-проект «Поставка ноутбуков» с двумя участниками открывается без AI-ключа.

> Отчёт носит рекомендательный характер и не заменяет решение закупочной комиссии. Перед подачей или
> отклонением заявки проверьте выводы по исходным документам.

## Возможности

- **Загрузка двух пакетов:** «Документация заказчика» и «Заявка участника».
  Поддерживаются PDF (с текстом и сканы), DOCX, DOC (упрощённо), RTF, ODT, TXT, XLSX/XLS/ODS/CSV, JPG/PNG/WEBP/BMP и ZIP
  (с кириллическими именами файлов). Тип документа (ТЗ, проект договора, сертификат, справка и т.д.) определяется автоматически.
- **OCR сканов и фото** выполняет мультимодальная LLM, с оценкой уверенности по каждой странице.
  Страницы, распознанные с низкой уверенностью, уходят на ручную проверку.
- **Чек-лист требований:** к товару и к участнику, атомарный (одно условие — одна строка). У каждой строки есть тип
  (обязательное / оценочное / желательное), оператор (≥, ≤, =, диапазон, допуск, наличие, текст, дата), способ подтверждения
  и источник с цитатой. Перед сравнением чек-лист можно отредактировать и утвердить.
- **Защита от галлюцинаций:** каждая цитата автоматически ищется в тексте документа. Требование без найденной цитаты
  в чек-лист не попадает.
- **Вопросы к заказчику:** противоречия (например, гарантия 36 мес в ТЗ и 12 мес в договоре), неоднозначности,
  требования, ограничивающие конкуренцию. Черновик запроса на разъяснение выгружается в DOCX.
- **Сопоставление с заявкой:** пять статусов (соответствует / частично / не подтверждено / не соответствует / требует проверки)
  с обоснованием и двумя ссылками на источники.
  - Числа сравнивает код, а не нейросеть, после приведения единиц: ГБ/МБ, мес/годы, кг/г, дюймы/мм, °F/°C, кд/м² = нит, тыс./млн сум и т.д.
  - Сроки действия документов проверяются на дату окончания приёма заявок.
  - Источники имеют приоритет: документ производителя или сертификат > техпредложение > маркетинг.
- **Скоринг по ТЗ:** S = Σ wᵢ·kᵢ / Σ wᵢ.
  - Веса: обязательное 3, оценочное 2 (или баллы из критериев оценки), желательное 1.
  - Коэффициенты k: 1 / 0,5 / 0,3 / 0.
  - Пункты «Требует проверки» исключаются из расчёта, вместо точного процента показывается диапазон «от–до».
  - Итог показывается отдельно по товару, по участнику и по категориям, плюс прогноз «если устранить все рекомендации — станет N%».
- **Вердикт:** «Риск отклонения», если хотя бы одно обязательное требование не выполнено (статус «Не соответствует»),
  при любом проценте. «Готова к подаче», если все обязательные требования зелёные. В остальных случаях (обязательные
  «частично», «не подтверждено» или «требует проверки») — «Требует доработки».
- **Рекомендации:** что не так, конкретное действие, тип действия, критичность, влияние на итог.
  Рекомендация никогда не предлагает исказить факты.
- **Повторная проверка** после дозагрузки исправленных документов и **история версий** (было 72% → стало 94%).
- **Разъяснения и изменения документации** обновляют чек-лист, изменённые пункты помечаются.
- **Несколько участников:** матрица «требование × участник».
- **Чат по проекту** отвечает только по загруженным документам.
- **Экспорт:** XLSX (чек-листы и сравнение), DOCX (запрос на разъяснение), JSON, печать отчёта в PDF.
- Интерфейс и отчёт на трёх языках: RU / UZ (латиница) / EN.

## Режимы работы

| Режим | Что нужно | Как включить |
|---|---|---|
| **Демо** | ничего | Открыть сайт и выбрать демо-проект. AI не вызывается. |
| **Свой ключ в браузере** | бесплатный ключ Google Gemini ([aistudio.google.com/apikey](https://aistudio.google.com/apikey)) или платный ключ OpenAI / Anthropic | «Настройки» → провайдер, ключ, модель. Ключ хранится только в localStorage вашего браузера и уходит напрямую провайдеру. |
| **Через прокси Cloudflare** | бесплатный аккаунт Cloudflare + бесплатный ключ Gemini | Развернуть [`proxy/`](./proxy/README.md) и указать его URL в «Настройки → Адрес API / прокси» или в переменной репозитория `PROXY_URL`. Посетителям ключ не нужен. |

Документы обрабатываются в браузере. На сервер ничего не загружается, проекты хранятся в IndexedDB браузера.
Текст документов отправляется только выбранному AI-провайдеру (напрямую или через ваш прокси).

## Локальный запуск

Нужен Node.js 22.18+ (рекомендуется 24).

```bash
npm i
npm run dev      # http://localhost:5173
npm test         # самотесты: единицы, скоринг демо, проверка цитат демо
npm run build    # сборка в dist/
```

Чтобы локально работать через прокси без ключа, создайте файл `.env.local` со строкой
`VITE_PROXY_URL=https://<ваш-воркер>.workers.dev`. Файл в git не попадает.

## Деплой на GitHub Pages

1. Загрузите репозиторий на GitHub (ветка `main`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Необязательно: разверните прокси по инструкции [`proxy/README.md`](./proxy/README.md). Затем в
   **Settings → Secrets and variables → Actions → Variables** добавьте переменную `PROXY_URL` с адресом воркера.
4. Каждый push в `main` запускает [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml): `npm ci` → `npm test` →
   `npm run build` → публикация. Запустить деплой вручную: **Actions → Deploy to GitHub Pages → Run workflow**.

Сайт будет доступен по адресу `https://massonedrew-dotcom.github.io/tender-sverka/`. Сборка использует относительные пути (`base: './'`),
поэтому работает под любым именем репозитория.

## Архитектура

Статичное SPA (React 19 + TypeScript + Vite + Tailwind), без своего сервера. Вся логика конвейера работает в браузере (`src/lib`):

- `extract.ts`: чтение форматов (pdf.js, mammoth, SheetJS, JSZip), OCR через LLM, классификация файлов.
- `pipeline.ts`: извлечение требований, разъяснения, разбор заявки, сопоставление, аналитический вывод, чат.
- `units.ts`: нормализация единиц и детерминированное сравнение чисел.
- `scoring.ts`: процент соответствия, диапазон «от–до», вердикт, прогноз, влияние пункта на итог.
- `text.ts`: нормализация текста, поиск и подсветка цитат.
- `llm.ts`: вызовы OpenAI Chat Completions (включая OpenAI-совместимый API Google Gemini) / Anthropic Messages с повторами и контролем ответа.

Принцип гибридный: LLM извлекает и интерпретирует, а числа, даты, статусы по правилам и итоговый процент считает код.
Подробнее: [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md).

## Ограничения MVP

- Нет серверной части: нет учётных записей, ролей, общего доступа к проектам и журнала на сервере. Данные живут в одном браузере,
  обмениваться ими можно экспортом JSON.
- OCR и разбор выполняет внешняя LLM. Точность зависит от модели и качества скана. Лимиты на страницы OCR настраиваются.
- Очень большие пакеты (сотни страниц) отправляются в модель частями. Если пакет заявки не поместился в лимит, ненайденные пункты
  получают статус «Требует проверки», а не «Не соответствует».
- RAR/7Z, DWG/DXF, HEIC/TIFF не поддерживаются: используйте ZIP, PDF, JPG или PNG. Старый формат DOC читается упрощённо.
- Проверки по внешним реестрам (ИНН, реестр недобросовестных исполнителей, лицензии) не реализованы, это вторая очередь.
- Повторный запуск AI может давать немного разные формулировки. Для воспроизводимости фиксируйте модель в настройках.

## Безопасность и конфиденциальность

- Секретов в репозитории нет. Ключ для общего доступа хранится только в секретах Cloudflare Worker.
- Ключ, введённый в «Настройках», хранится в localStorage этого браузера. Не вводите его на чужом компьютере.
- Документы уходят во внешний AI-API. Перед загрузкой проверьте, допустимо ли это для ваших данных
  (в том числе требования законодательства РУз о персональных данных).

## Дисклеймер

«Тендер-Сверка» — вспомогательный инструмент. Результаты сверки, проценты, вердикты и рекомендации носят рекомендательный
характер, могут содержать ошибки распознавания и интерпретации и не являются юридическим заключением. Окончательное решение
о подаче, допуске или отклонении заявки принимает пользователь или закупочная комиссия по исходным документам.
Все организации и реквизиты в демо-проекте условные.
