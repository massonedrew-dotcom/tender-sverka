# Дорожная карта «Тендер-Сверка»

Этапы согласованы с разделом 12 ТЗ (исследование → MVP → пилот → расширение) и с ограничением «без сервера» на старте. Открытые вопросы раздела 13 обозначены **В13.n** в порядке их следования в ТЗ:

- В13.1 — где живёт продукт: отдельный сервис, TenderZone или TenderGPT;
- В13.2 — первичный клиент: поставщик или заказчик;
- В13.3 — виды закупок;
- В13.4 — отрасли эталонного набора и кто его размечает;
- В13.5 — облако или on-premise, допустимость внешних AI-API;
- В13.6 — монетизация;
- В13.7 — дисклеймер;
- В13.8 — название.

---

## Этап 0 — MVP-демо (текущий)

**Цель:** показать полный сквозной сценарий в браузере без сервера. Покрывает «MVP» из раздела 12 ТЗ в объёме, возможном без бэкенда.

| Задача | Критерий приёмки |
|---|---|
| Конвейер в браузере: приём → чек-лист → сопоставление → скоринг → вывод | Демо-лот открывается без ключа. С ключом или прокси лот из `demoSampleFiles()` проходит весь путь без ошибок. |
| Экраны Projects, Upload, Checklist, Compare, Summary, Matrix, History, печать PDF | Все 7 экранов из раздела 9 ТЗ доступны; клик по пункту открывает обе цитаты с подсветкой. |
| Экспорт XLSX, DOCX, JSON, PDF | Файлы открываются в Excel/Word, PDF печатается из браузера. |
| Деплой на GitHub Pages и прокси Cloudflare Worker | Сборка из `main` публикуется автоматически; через прокси AI работает без ключа у пользователя. |
| Интерфейс RU / UZ / EN | Нет захардкоженных русских строк в UI. |
| Исправить critical- и major-замечания код-ревью | См. отчёт архитектора: подмена ID после повторного извлечения, `ok` без подтверждения документом, слияние разъяснений, лимиты токенов. |
| Документация | `docs/ARCHITECTURE.md`, `TZ_COVERAGE.md`, `ROADMAP.md`, README с инструкцией по прокси. |

**Решения, нужные до показа:** В13.7 — дисклеймер «отчёт носит рекомендательный характер» (предлагается показать его в сводке и PDF); В13.8 — название.

## Этап 1 — Пилот и измерение качества

**Цель:** измерить критерии приёмки из раздела 12 ТЗ на реальных данных и выбрать модель (раздел 11 ТЗ: «выбор модели по тесту на 20–30 тендерах»). Пилот — 5–10 компаний-поставщиков (раздел 12 ТЗ, «Пилот»).

**Предусловия:** ответы на В13.2 (кто клиент: от этого зависит, что приоритетнее — самопроверка или матрица N заявок), В13.3 (виды закупок), В13.4 (отрасли, эксперт-разметчик, сроки), В13.5 (можно ли отправлять реальные документы во внешние API).

| Задача | Критерий приёмки |
|---|---|
| **Эталонный набор**: 20–30 тендеров с заявками (товары, работы, услуги; текстовые PDF, сканы, фото, чертежи; uz/ru/en) с ручной разметкой эксперта: чек-лист и статусы | Разметка в формате `types.ts` (JSON); 2 разметчика на 20% набора, согласие ≥ 90%. |
| **Скрипт оценки** (`scripts/eval`): прогон конвейера на наборе и сравнение с эталоном | Отчёт: recall обязательных требований, точность статусов, доля `review`, число ложных `ok` по обязательным, доля пунктов со ссылкой, время на 100 страниц, стоимость прогона. |
| **Сравнение 2–3 моделей** (OpenAI, Claude, при необходимости Gemini) на OCR и извлечении | Таблица метрик, цены и времени по моделям; выбор модели по умолчанию с обоснованием. |
| **Фиксация версий** модели и промптов в результатах (`Version`, `Analysis`) + кэш результатов по хэшу «файл + промпт + модель» | Повторный запуск на тех же файлах даёт идентичный отчёт (раздел 10 ТЗ, «Воспроизводимость»). |
| **Доводка защиты от галлюцинаций**: минимальная длина цитаты; уверенность OCR ниже 90% → `review`; оператор `date` кодом; «или эквивалент» не выше `review` | 0 ложных `ok` по обязательным на наборе (блокирующий критерий из раздела 12 ТЗ). |
| **Сопоставление для больших пакетов**: в промпт передаются только релевантные страницы (поиск BM25 или эмбеддинги в браузере), предупреждение об усечении | Пакет 300 страниц проходит без потери пунктов; в отчёте нет «отсутствует», если подтверждение есть в пакете. |
| **Промежуточные результаты** и устойчивость к сбоям: сбой пакета → `review`, а не падение прогона | Прогон всегда завершается; готовые пункты видны по мере обработки. |
| **Сбор обратной связи пилота**: кнопка «статус неверен» и экспорт журнала ошибок | Не меньше 100 размеченных ошибок пилота для следующей итерации. |
| **Оценка рекомендаций экспертом** | Не меньше 80% рекомендаций применимы (раздел 12 ТЗ). |

**Целевые пороги выхода из Этапа 1** (раздел 12 ТЗ): recall обязательных 100%; точность статусов 100% без учёта `review`; доля `review` ≤ 15%; 0 ложных «Соответствует»; 100% ссылок рабочие; 100 страниц ≤ 10 мин; рекомендации применимы ≥ 80%. Если порог по OCR не достигается в браузере, это аргумент для Этапа 2, шаг «распознавание на сервере».

## Этап 2 — Серверная архитектура

**Цель:** выполнить нефункциональные требования раздела 10 ТЗ, которые невозможны в браузере, и перейти к целевому стеку раздела 11. Порядок шагов описан в `ARCHITECTURE.md` §10.

**Предусловия:** В13.1 (отдельный сервис или компонент TenderZone/TenderGPT определяет авторизацию и хостинг), В13.5 (облако или on-premise; локализация персональных данных в РУз), В13.6 (монетизация определяет учёт: проверки или страницы), бюджет на инфраструктуру.

| Задача | Критерий приёмки |
|---|---|
| LLM-шлюз на FastAPI (вместо прокси): ключи, лимиты, учёт затрат, журнал промптов | Ключи не попадают в браузер; затраты видны по компании и проверке. |
| PostgreSQL + S3: проекты, файлы-оригиналы, версии; AES-256 на хранении; TLS 1.2+ | Изоляция данных компаний подтверждена тестами; срок хранения настраивается (по умолчанию 12 мес), удаление по запросу. |
| Аутентификация и роли (администратор, специалист, просмотр), журнал действий, вход по телефону / SSO площадки | Соответствие строке «Доступ» раздела 10 ТЗ. |
| Очередь (Celery/RabbitMQ) и постраничная обработка | 100 страниц ≤ 10 мин, 500 страниц ≤ 30 мин; ≥ 50 одновременных проверок с горизонтальным масштабированием. |
| Серверное распознавание: специализированный OCR для таблиц, предобработка, RAR/7Z, TIFF/HEIC, bbox фрагментов | CER ≤ 2% (скан ≥ 200 dpi) и ≤ 5% (фото) на наборе Этапа 1; подсветка области на странице. |
| pgvector: поиск подтверждений в больших пакетах | Recall сопоставления на пакетах свыше 500 страниц не ниже, чем на малых. |
| Порт `units.ts` и `scoring.ts` на Python с общими тест-векторами | Результаты TS и Python совпадают на демо-лоте и эталонном наборе. |
| REST API (OpenAPI) и выгрузка JSON | Внешняя система создаёт проверку и получает отчёт через API. |
| Доступность 99,5%, мониторинг, бэкапы | SLA-метрики за месяц. |

## Этап 3 — Расширение: режим заказчика и интеграции

Соответствует пункту «Расширение» раздела 12 ТЗ.

**Предусловия:** В13.1, В13.2 (если первичный клиент — поставщик, режим заказчика идёт сюда; если заказчик — матрица N заявок поднимается в Этап 1), договорённости с TenderZone/TenderGPT.

| Задача | Критерий приёмки |
|---|---|
| Полный режим заказчика: N заявок, матрица «требование × участник», сравнительный отчёт комиссии | Отчёт по каждому участнику и сводный — в PDF/XLSX; время на N заявок растёт линейно. |
| Интеграция TenderZone: импорт лота по ссылке, фаза «проверка комплекта документов» | Лот импортируется по ссылке без ручной загрузки (раздел 3.1 ТЗ, «Прочее»). |
| Встраивание в TenderGPT как модуль комиссии | Работа внутри TenderGPT с единым входом. |
| Проверка по внешним реестрам: ИНН, недобросовестные исполнители, лицензии (модуль проверки контрагентов TenderZone) | Статусы U-пунктов «реестр» вычисляются автоматически с датой проверки (раздел 5 ТЗ). |
| DWG/DXF | Данные штампа и размеры извлекаются из DWG/DXF (раздел 3.3 ТЗ). |
| Администрирование: справочники синонимов параметров, шаблоны весов под площадку | Роль «Администратор» из раздела 2 ТЗ. |
| Расширенные языки (китайский, турецкий, казахский и др.) с метриками | Точность на подмножестве набора с этими языками. |

## Сквозные риски

| Риск | Митигация |
|---|---|
| Запрет на передачу документов во внешние AI-API (В13.5) | Этап 2 с моделью в локальном контуре или у провайдера с хранением в РУз; на пилоте — только разрешённые данные. |
| Стоимость LLM на больших пакетах | Отбор релевантных фрагментов (Этап 1), кэш, более дешёвая модель для OCR и фактов. |
| Целевые 100% recall и точности недостижимы без человека | Порог `review` и обязательное утверждение чек-листа. Метрика «0 ложных ok» — блокирующая. |
| Лимиты бесплатного Cloudflare Worker и rate limit провайдеров | Ограничение частоты в воркере, очередь на Этапе 2. |
